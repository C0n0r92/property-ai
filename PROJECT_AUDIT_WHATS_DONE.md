# Property-ML Implementation Audit (What Is Done)

## Purpose of This Document

This document captures what is already implemented in the `property-ml` project so future planning can focus on gaps, hardening, and prioritization rather than rediscovery.

---

## Project At A Glance

`property-ml` is a Dublin property market intelligence platform with three main parts:

1. `dashboard` - Next.js web app for users
2. `scraper` - Playwright-based data ingestion pipelines
3. `scripts` - analysis and content-generation tooling (mainly blog analytics)

The platform already supports market data ingestion, consolidation, property discovery UX, account features, premium/payment flows, and data-driven blog content.

## What Is Implemented: Scraper (`scraper`)

### End-to-End Pipeline

Implemented pipeline supports:

1. Scrape sold properties from Daft.ie
2. Scrape active listings from Daft.ie
3. Scrape rentals from Daft.ie
4. Enrich with geocoding and derived metrics
5. Persist dated snapshots to JSON
6. Consolidate historical snapshots into unified datasets
7. Optionally upsert/upload to Supabase
8. Optionally copy or expose consolidated outputs for dashboard use

### Pipeline Modules in Place

- `src/pipeline-incremental.ts` - sold scrape flow
- `src/pipeline-open.ts` - listing scrape flow
- `src/pipeline-rentals.ts` - rental scrape flow
- `src/scraper-utils.ts` - shared browser/scraper primitives
- `src/geocode.ts` - geocoding/enrichment
- `src/database.ts` - Supabase persistence
- `src/consolidate-new.ts` - dedupe + merge + enrich consolidated output
- `src/update-parallel.ts` - orchestration runner
- `src/upload-to-supabase.ts` - upload pipeline

### Data Outputs Already Implemented

- Dated JSON snapshots in:
  - `scraper/data/sold/`
  - `scraper/data/listings/`
  - `scraper/data/rentals/`
- Consolidated `data.json` style outputs
- Historical dated consolidated files (where generated by script flow)

### Enrichment and Derived Metrics

- Address normalization/geocoding
- Basic pricing metrics (for example per sqm where data exists)
- Listing/rental history concepts during consolidation
- Yield estimation logic based on available rental/sold context
- Area-level statistics generation

### Scheduling and Operations

- Daily run scripts and setup support exist
- Local cron setup helper exists
- Droplet/server bootstrap script exists

## Known Implementation Gaps / Risks (Important For Planning)

This section documents observed maturity gaps while acknowledging core functionality is already in place.

### Security and Secrets

- Secret-management hygiene appears inconsistent across repo artifacts.
- Credentials should be audited/rotated and removed from tracked files where applicable.

### System Consistency

- Some duplication/drift exists:
  - blog/research route overlap
  - multiple chart output locations
  - mixed legacy/current artifacts in root

### Script Reliability and Tooling Drift

- Some scripts and script references appear stale or inconsistent.
- Path assumptions vary across analysis scripts.

### Data Correctness Hardening

- Scraping and parsing edge cases need stricter validation and QA checks.
- Consolidation correctness should be reinforced with tests/guards.

### Documentation and Onboarding

- No single authoritative root runbook for full local bring-up.
- Existing docs are useful but fragmented and partially stale.
